# 卫通会议（云端）· 部署

本文说明如何把本树源码跑到一台服务器上对外提供服务。本地改代码见 [本地开发.md](./本地开发.md)。

## 1. 架构（部署视角）

```
浏览器 ──HTTPS──► 反向代理(80/443)
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
   前端静态文件              后端 :8082
   (Vue build 产物)         (Go 二进制 + SQLite)
          │                       │
          └──── /api /ws /assets ─┘  （同源反代）
```

- 本应用：登录、日程、设置、会中信令、偏好。  
- 音视频媒体：三方会议平台（配置里的 `thirdParty.conference.baseUrl`）。  
- 公网入口必须是 **HTTPS**（麦克风/摄像头需要安全上下文）。

## 2. 机器要求

| 项 | 建议 |
| --- | --- |
| OS | Linux x86_64（或同等 amd64） |
| 运行时 | 已安装 Go（编译用）、Node/pnpm（编译前端用）；运行期只需二进制 + 静态文件 + 反代 |
| 磁盘 | 本地盘放 SQLite（`data/`），不要用 NFS |
| 出网 | 能访问三方会议 API；若发邮件验证码，能连 SMTP |
| 端口 | 对外 443（或 80→跳转 HTTPS）；本机后端 8082 仅内网 |

## 3. 准备配置

```bash
cd cloud/backend
cp manifest/config/config.yaml.example manifest/config/config.yaml
```

编辑 `config.yaml`（口令位不要提交进 git）：

| 关键项 | 说明 |
| --- | --- |
| `deployment.side` | 保持 `cloud` |
| `server.address` | 生产建议 `:8082` |
| `thirdParty.conference.baseUrl` | 三方控制面地址 |
| `jwt.secret` | 换成足够长的随机串 |
| `auth.autoLogin.enabled` | 公网必须 `false` |
| `auth.email.*` | 需要邮箱验证码时配 SMTP |

可选：准备 `manifest/sql/seed-credentials.sql`（gitignore）写入测试账号三方口令，首次迁移时注入。

## 4. 编译

### 4.1 后端

```bash
cd cloud/backend
go mod download
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o conference .
```

得到可执行文件 `conference`（Linux 上部署就在 Linux 上编，或交叉编译 `GOOS=linux GOARCH=amd64`）。

### 4.2 前端

```bash
cd cloud/frontend
pnpm install
pnpm build
```

产物在 `frontend/dist/`。

## 5. 落盘与启动后端

建议目录（示例）：

```text
/opt/conference/
├── conference              # 后端二进制
├── manifest/
│   ├── config/config.yaml
│   └── sql/sqlite_create.sql   # 及可选 seed-credentials.sql
├── data/                   # SQLite 写这里（conference.db）
└── www/                    # 前端 dist 内容拷到这里
```

```bash
mkdir -p /opt/conference/{data,www,manifest/config,manifest/sql}
cp cloud/backend/conference /opt/conference/
cp cloud/backend/manifest/config/config.yaml /opt/conference/manifest/config/
cp cloud/backend/manifest/sql/sqlite_create.sql /opt/conference/manifest/sql/
# 若有 seed-credentials.sql 一并拷入 manifest/sql/
cp -r cloud/frontend/dist/* /opt/conference/www/

cd /opt/conference
./conference
```

后端默认听 `:8082`。库文件出现在 `data/conference.db`（相对进程工作目录；请在 `/opt/conference` 下启动，或改配置里的 sqlite 路径）。

可用 systemd 托管，例如：

```ini
[Unit]
Description=conference-cloud
After=network.target

[Service]
WorkingDirectory=/opt/conference
ExecStart=/opt/conference/conference
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## 6. 反向代理（必做）

用 nginx / Caddy / 云负载均衡均可，原则：

1. 静态：`/` → `/opt/conference/www`  
2. 反代：`/api`、`/ws`、`/assets` → `http://127.0.0.1:8082`（WebSocket 要升级头）  
3. 对外只暴露 HTTPS；**不要**把 `8082` 直接映射到公网  
4. 公网关闭 swagger：勿反代 `/swagger`、`/api.json`（或后端配置里关掉）

nginx 片段示例：

```nginx
server {
  listen 443 ssl;
  server_name your.domain;

  # ssl_certificate ...;
  # ssl_certificate_key ...;

  root /opt/conference/www;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    proxy_pass http://127.0.0.1:8082;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location /assets/ {
    proxy_pass http://127.0.0.1:8082;
    proxy_set_header Host $host;
  }

  location /ws {
    proxy_pass http://127.0.0.1:8082;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
  }
}
```

## 7. 验收

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://your.domain/api/v1/dicts/meeting_status
# 期望 200
```

浏览器打开 HTTPS 登录页；手机麦克风需安全上下文（HTTPS）。

## 8. 升级

1. 停后端  
2. 替换二进制与 `www/` 静态文件（保留 `data/`）  
3. 若有 SQL 变更，按 `docs/数据库结构.md` 迁移  
4. 启动后端，再刷前端强缓存（`index.html` 勿长期缓存）
