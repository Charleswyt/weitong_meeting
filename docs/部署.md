# 卫通会议（云端）· 部署

本文说明如何把本树源码跑到一台服务器上对外提供服务。本地改代码见 [本地开发.md](./本地开发.md)。

## 1. 架构（部署视角）

```
浏览器 ──HTTPS──► 反向代理(80/443)
                      │
          ┌───────────┴───────────┐
          ▼                       ▼
   前端静态文件              后端 :8082
   (Vue build 产物)         (Go 二进制 + SQLite)
          │                       │
          └──── /api /ws /assets ─┘  （同源反代）
```

- 本应用：登录、日程、设置、会中信令、偏好。  
- 音视频媒体：三方会议平台（配置里的 `thirdParty.conference.baseUrl`）。  
- 公网入口必须是 **HTTPS**（麦克风/摄像头需要安全上下文）。

## 2. 机器要求

| 项 | 建议 |
| --- | --- |
| OS | Linux x86_64（或同等 amd64） |
| 运行时 | 已安装 Go（编译用）、Node/pnpm（编译前端用）；运行期只需二进制 + 静态文件 + 反代 |
| 磁盘 | 本地盘放 SQLite（`data/`），不要用 NFS |
| 出网 | 能访问三方会议 API；若发邮件验证码，能连 SMTP |
| 端口 | 对外 443（或 80→跳转 HTTPS）；本机后端 8082 仅内网 |

## 3. 准备配置

```bash
cd cloud/backend
cp manifest/config/config.yaml.example manifest/config/config.yaml
```

编辑 `config.yaml`（口令位不要提交进 git）：

| 关键项 | 说明 |
| --- | --- |
| `deployment.side` | 保持 `cloud` |
| `server.address` | 生产建议 `:8082` |
| `thirdParty.conference.baseUrl` | 三方控制面地址 |
| `jwt.secret` | 换成足够长的随机串 |
| `auth.autoLogin.enabled` | 公网必须 `false` |
| `auth.email.*` | 需要邮箱验证码时配 SMTP |

可选：准备 `manifest/sql/seed-credentials.sql`（gitignore）写入测试账号三方口令，首次迁移时注入。

## 4. 编译

### 4.1 后端

```bash
cd cloud/backend
go mod download
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o conference .
```

得到可执行文件 `conference`（Linux 上部署就在 Linux 上编，或交叉编译 `GOOS=linux GOARCH=amd64`）。

### 4.2 前端

```bash
cd cloud/frontend
pnpm install
pnpm build
```

产物在 `frontend/dist/`。

## 5. 落盘与启动后端

建议目录（示例）：

```text
/opt/conference/
├── conference              # 后端二进制
├── manifest/
│   ├── config/config.yaml
│   └── sql/sqlite_create.sql   # 及可选 seed-credentials.sql
├── data/                   # SQLite 写这里（conference.db）
└── www/                    # 前端 dist 内容拷到这里
```

```bash
mkdir -p /opt/conference/{data,www,manifest/config,manifest/sql}
cp cloud/backend/conference /opt/conference/
cp cloud/backend/manifest/config/config.yaml /opt/conference/manifest/config/
cp cloud/backend/manifest/sql/sqlite_create.sql /opt/conference/manifest/sql/
# 若有 seed-credentials.sql 一并拷入 manifest/sql/
cp -r cloud/frontend/dist/* /opt/conference/www/

cd /opt/conference
./conference
```

后端默认听 `:8082`。库文件出现在 `data/conference.db`（相对进程工作目录；请在 `/opt/conference` 下启动，或改配置里的 sqlite 路径）。

可用 systemd 托管，例如：

```ini
[Unit]
Description=conference-cloud
After=network.target

[Service]
WorkingDirectory=/opt/conference
ExecStart=/opt/conference/conference
Restart=on-failure

[Install]
WantedBy=multi-user.target
```

## 6. 反向代理（必做）

用 nginx / Caddy / 云负载均衡均可，原则：

1. 静态：`/` → `/opt/conference/www`  
2. 反代：`/api`、`/ws`、`/assets` → `http://127.0.0.1:8082`（WebSocket 要升级头）  
3. 对外只暴露 HTTPS；**不要**把 `8082` 直接映射到公网  
4. 公网关闭 swagger：勿反代 `/swagger`、`/api.json`（或后端配置里关掉）

nginx 片段示例：

```nginx
server {
  listen 443 ssl;
  server_name your.domain;

  # ssl_certificate ...;
  # ssl_certificate_key ...;

  root /opt/conference/www;
  index index.html;

  location / {
    try_files $uri $uri/ /index.html;
  }

  location /api/ {
    proxy_pass http://127.0.0.1:8082;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
  }

  location /assets/ {
    proxy_pass http://127.0.0.1:8082;
    proxy_set_header Host $host;
  }

  location /ws {
    proxy_pass http://127.0.0.1:8082;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection "upgrade";
    proxy_set_header Host $host;
    proxy_read_timeout 3600s;
  }
}
```

## 7. 验收

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://your.domain/api/v1/dicts/meeting_status
# 期望 200
```

浏览器打开 HTTPS 登录页；手机麦克风需安全上下文（HTTPS）。

## 8. 升级

1. 停后端  
2. 替换二进制与 `www/` 静态文件（保留 `data/`）  
3. 若有 SQL 变更，按 `docs/数据库结构.md` 迁移  
4. 启动后端，再刷前端强缓存（`index.html` 勿长期缓存）

## 10. 独立板卡入口与共用会场

公网与板卡使用同一份 Vue 构建，资源前缀是 `/zwt-meeting/`。板卡运行 `weitong-edge.service`，账号、预约与会场状态均由公网管理。在板卡局域网访问 `https://<板卡局域网IP>:38765/zwt-meeting/`。浏览器需信任包含该 IP 的平台证书才能使用摄像头和麦克风。

1. 在仓库的 `frontend` 运行 `pnpm exec vite build --base=/zwt-meeting/`，将产物放入发布目录的 `dist/`。在 `backend` 运行 `CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -o ../release/edge ./cmd/edge`。
2. 用 `python3 deploy/edge/build_uplink.py <Ocean SDK 的 tools/h264_whip_publisher> release/uplink` 构建 WAN 发布工具。将 `deploy/edge/` 下的 `install.py`、`prepare_media.py`、`weitong-edge.service`、`weitong-edge-media.service` 复制到发布目录。为这些文件、两个可执行文件和全部前端资源生成 `files.json`，内容为相对路径到 SHA-256 小写十六进制摘要的 JSON 对象，清单不包含自身。
3. 板卡需安装 Ocean 媒体底座，包含本机 MediaMTX、`h264_whip_publisher`、`mpp_dec_roi_bench` 和可供服务账号使用的 RK 设备。以 root 执行 `python3 release/install.py release <板卡平台配置路径> <已核对的云端 PEM 证书> --ip <板卡局域网IP> --origin https://<会议公网地址>`。安装器校验发布包，生成该板的独立 Ed25519 密钥并返回节点 ID、公钥及独立网址。
4. 将返回的节点 ID 与公钥写入云端 `WEITONG_EDGE_KEYS` 指定的 JSON 对象，保留其他已登记节点。`systemctl status weitong-edge` 可检查服务，登录独立页面后用 `GET /api/v1/settings/capabilities` 核对 `accessNode=edge`。测试时用另一账号从公网加入同一会议，双向检查摄像头和麦克风。

开机时，`weitong-edge-media.service` 为会议服务账号准备原生程序和设备权限，并检查本地 Ocean 会议媒体服务。已有服务可直接复用。硬件编码持续运行时，晚入会的浏览器会发送关键帧请求。发布程序将请求交给对应摄像头的编码器。验收时应先开启摄像头，几秒后再让另一端订阅，并检查接收端已解码帧数是否增长。

当前中卫通板卡版的部署范围为 RK3588 的 001、LAB、BJ3、ATK122 和 UB20-001。RK3576-002 和 RK3568-119 继续由底座运维，不部署本会议服务。

云端中卫通 Go 服务通过回环访问 Ocean。配置 `THIRDPARTY_CONFERENCE_BASEURL`、公网媒体来源 `WEITONG_OCEAN_ORIGIN` 及 `WEITONG_OCEAN_ACCOUNT_KEY`。共用密钥由服务器生成，至少 32 字节，仅授予签发和验证服务读取权限。在 Ocean 主控同目录放入 `deploy/ocean/weitong_federation.py`，用 `install_hooks.py <已备份的原版主控> <候选主控>` 生成待部署版本。原版变更导致补丁无法准确适用时需要重新核对。`/etc/weitong-ocean/` 存放 `account.key`、运维查询凭证 `presence.key`、指向现有维护截止文件的 `drain` 以及可执行的 `media-reader`。最后一项使用同架构的 `uplink` 二进制，为旧版 Ocean/海星客户端读取 H.264 帧。原码流传给这些客户端时只重新封装。

在原公网会议运维服务使用 `deploy/ocean/install_activity.py <原服务> <候选服务>` 接入 `WEITONG_OCEAN_PRESENCE_URL=http://127.0.0.1:8092/internal/weitong/rooms`。公网发布前检查 ROI 在会读数、原生会场成员和媒体订阅，进入维护窗口后再查一次。保留原控制程序、配置、数据库备份和上个发布目录。回滚时成套恢复云端控制程序及静态目录，保持数据库和已完成录制。
