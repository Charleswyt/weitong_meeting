## 当前公网版本的压缩比与本端带宽

阿里云发布版本为 `20261122-cloud-ratio-267bef450f93`。开启软件压缩时，媒体服务用同一路摄像头或屏幕的云端实测视频输入码率除以单份编码输出码率，按两位小数返回。发布者和观看者显示同一个 `streams[].compressionRatio`。原始转发显示“直传”，采样不足或码率为零时显示“—”。

左侧会议信息保留会议号、人数和时长。左侧和传输状态中的本端带宽均只显示本端媒体上行、下行。传输状态可切换摄像头和共享屏幕，查看各自的云端压缩比。云端输入输出的采样值保留在调试接口。逐路字段与响应示例见 [公网 Apipost 1.5.0](https://47.114.83.151/zwt-meeting/apipost.json)。

## 设置与接口

| 传输方式 | 策略 | 云端行为 |
| --- | --- | --- |
| 原始转发 | 无 | 将源编码转给观看者，本地预览使用本机采集轨 |
| 阿里云软件压缩 | `source_frames` 原始帧率 | 逐帧处理已解码的输入，保留源时间戳，用目标码率重新编码 H.264 |
| 阿里云软件压缩 | `bandwidth_first` 动态帧率 | 根据码率预算、编码结果和画面内容调整输出帧率 |
| 阿里云软件压缩 | `optimized` 优化策略 | 动态帧率、全帧 AQ、渐进刷新。输入短边 ≤720 像素时限制在 360p，更高时限制在 540p，保留长宽比并对齐偶数像素 |

网页为当前账号在本机保存两路偏好。正在发布时，应用后由云端返回 `revision`。收到新版本的观看端重新订阅 WHEP，发布端继续使用已有 WHIP 和发布 ID。麦克风有独立的音频轨，屏幕共享可携带系统音轨。浏览器上行码率和云端压缩目标码率可分别配置。

| 接口 | 凭据与用途 |
| --- | --- |
| `POST /meetings/{id}/publications` | 使用会议网页账号 Bearer，创建摄像头、屏幕或独立音频发布。视频可以直接指定云端策略 |
| `PUT /meetings/{id}/publications/{pubId}/settings` | 本路发布者的网页账号 Bearer。启用压缩时传 `transportMode`、`encodingStrategy` 和 `targetBitrateKbps`。恢复原始转发可仅传 `{"transportMode":"original"}` |
| `GET /meetings/{id}/state`、WebSocket 的 `streams` 帧 | 查看逐路的输出版本、生效策略、目标码率、可播放状态和实测码率 |
| `POST /rooms/{roomId}/streams`、`PATCH /rooms/{roomId}/streams/{streamId}` | 供媒体层直接联调，使用所属发布者的参会令牌。媒体层字段为 `mode`、`encodingStrategy`、`videoKbps` |

HTTP 根路径为 `/zwt-meeting/api/v1`。集合的第 06 组按实际网页调用顺序提供登录、建会、入会、发布、切换三档、读取状态和停流示例。完整定义见 [OpenAPI](../contracts/api.openapi.yaml) 和 [Apipost 集合](../contracts/中卫通公网会议_Apipost接口集合.json)。

## 验证记录

阿里云隔离媒体实例使用已部署 Ocean 的原生可执行文件和对应的 x264 库，以 1280×720、25 fps 的运动测试图作为输入。三档均配置 100 kbps。按已解码画面的时间戳统计，原始帧率档为 25 fps，动态帧率档为 1.5 fps，优化档为 12.5 fps、640×360。优化档还解码到共享屏幕的 Opus 音轨。这里的帧率是该片段和码率下的样本。

发布时，首个候选业务二进制的 CPU 架构与云主机不符，健康检查触发回退。正式包针对 ARM64 构建，切换前校验候选和在运行二进制的 ELF 架构。云端软件压缩运行时另外保存所用二进制、共享库和脚本的 SHA-256 清单。

公网版本 `20261121-compression-56a69187e26e` 使用两个独立会议账号、两个浏览器和模拟摄像头验收。摄像头在同一发布 ID 中依次切到三档 H.264 和原始 VP8，对端每次都实际解出连续帧。四次回执的 `revision` 依次为 2、3、4、5。重复提交保持版本，其他成员修改本路被拒，历史值 `dynamic_gop` 在新设置接口被拒。另一次共享屏幕在首次发布时使用优化策略，远端解出 960×540 的 H.264。

公网摄像头往返测试使用 480p、上行上限 150 kbps，云端视频目标 100 kbps。720p 运动画面的三档帧率取自隔离测试。实际公网丢包时、共享画面长时间静止时，首帧等待有波动，本轮没有测定可承诺的启动时延。

## 逐路视频状态与原始帧率修订

公网版本 `20261121-video-stats-709715fb38a6` 在会中「传输状态」增加视频线路选择。主讲人、自己的摄像头以及任何人的共享屏幕都可按线路查看。设置中的浏览器视频上行上限与阿里云压缩目标分别控制两次编码。

| 字段 | 来源和单位 |
| --- | --- |
| `targetBitrateKbps` | 云端编码配置目标，kbps |
| `videoStats.cloudInputKbps`、`cloudOutputKbps` | 阿里云压缩前与分发路径输出的视频有效载荷，kbps。音频、传输开销及观看人数均不参与 |
| `videoStats.captureFps`、`publishFps` | 发布浏览器实测的采集源和发送编码帧率 |
| `videoStats.cloudInputFps`、`cloudOutputFps` | 阿里云网关接收与可供观看者订阅的输出视频帧率 |

视频线路用 `GET /meetings/{id}/state` 或 WebSocket 的 `streams` 事件读取。发布端通过已有 `POST /meetings/{id}/telemetry` 上报，服务端按参会身份和发布号归属接收。云端网关以约四秒窗口对实际视频帧和字节计数。准备中、单人待机的输出和过期的浏览器样本用 `null` 表示，测到零返回 `0`。压缩目标与协商帧率只作配置。原始转发的输入和输出共用一份采样，按观众累计的公网下行通过 WebRTC 观看连接单独统计。Apipost 集合版本为 1.3.0。

浏览器发布与换轨使用该轨实际协商规格。原始帧率编码器保留上云后可以解码的每一帧。对旧版和新版 C 选帧函数输入同一组 300 帧、平均 30 fps、交替提前 8 ms 的时间戳，原始帧率档分别保留 150 帧和 300 帧。相同输入在 12 fps 的动态选帧测试中，两版都选出 120 帧。

### 公网和隔离验收

公网使用两个独立 Chromium 浏览器与模拟摄像头。保持发布号并依次切换策略，以下是接收方读取的五个状态样本的中位数。三种云端编码均设置 100 kbps，接收端均实际解出 H.264。

| 模式 | 采集 fps | 浏览器发送 fps | 云端输入 fps | 云端输出 fps | 实测输入 / 输出 kbps |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原始帧率 | 30 | 30 | 30.2 | 29.9 | 653.5 / 94.0 |
| 动态帧率 | 30 | 30 | 29.7 | 21.5 | 645.9 / 92.4 |
| 优化策略 | 30 | 30 | 21.7 | 21.7 | 493.4 / 79.9 |
| 恢复原始转发 | 30 | 30 | 29.7 | 29.7 | 650.6 / 650.6 |

云端隔离环境以同一条 1280×720、30 fps 运动测试图和 100 kbps 目标测试。原始帧率、动态帧率和优化策略的网关输出分别测到 30、3、12 fps，优化输出为 640×360。原始帧率在这个复杂画面上实测输出 420 kbps，体现了保帧策略与码率目标之间的取舍。另用两个公网浏览器验证独立共享屏幕，观看端解出 960×540 H.264；采集 20 fps、云端输入和输出均约 19.9 fps。

共享屏幕的低上行测试中，一次云端编码器在 45 秒内未收到可解码首帧。相同的 10 fps、150 kbps 浏览器上行上限复测成功，云端输入 10 fps、优化输出 6.5 fps，观看端解出了画面。此次测试使用模拟摄像头和屏幕采集。媒体服务本地提交为 `3cecc2e5`。


## 单人压缩、本地预览与计量（2026-11-22）

公网版本 `20261122-local-preview-621530ba4e64`。本机画面绑定本地摄像头或共享轨道，发布连接为 sendonly。云端收到持续发布的源流就启动所选编码器。观看端全部离开后，发布号和输出版本可继续使用。停止该路发布、离会或结束会议时，底层释放相应媒体资源。

| 读数 | 采样位置与计算 |
| --- | --- |
| 解码后原始速率 | 发布端在相机效果前或共享屏幕源上统计实际可见帧。累计 `VideoFrame.allocationSize()` 的字节数，再按实际采样秒数换算为 kbps。帧在本地释放。浏览器未提供像素格式或该窗口缺样时显示「—」。[WebCodecs 规范](https://www.w3.org/TR/webcodecs/#dom-videoframe-allocationsize) |
| 发布端视频上行 | 同一发布的 `outbound-rtp.bytesSent` 增量除以采样时长，换算为 kbps。麦克风单独统计。[WebRTC Stats 规范](https://www.w3.org/TR/webrtc-stats/#dom-rtcsentrtpstreamstats-bytessent) |
| 云端接收与云端输出 | 在阿里云分别测量输入和单份分发输出的视频有效载荷。配置的目标码率独立列出。 |
| 本端视频实收 | 观看端同一路视频的 `inbound-rtp.bytesReceived` 增量除以实际经过的时间，再换算为 kbps。 |
| 公网媒体下行 | 云端对实际 WebRTC 观看连接计量。无人观看时为 0 kbps，本机本地预览和云内编码器读取均不产生该项流量。 |

Ocean 媒体仓库里，`frontend/dist/assets/ocean-meeting.js` 的 `samplePeerRates` 分音频、视频读取收发计数，`compressionText` 接收相应两侧的实测速率。中卫通沿用 Ocean 网页发布的算法。看自己时用发布端视频上行除以云端视频输出，看远端时优先除以本机实际收到的该路视频速率，接收采样未就绪时回到云端输出。解码后原始速率独立展示。原始转发显示「直传」。浏览器先将画面编码后上行，开启阿里云软件压缩时，云端再解码并按所选策略重编码。

个人设置和会中设置按账号分别保存摄像头、共享屏幕的策略。线路在会中切换时，左侧会议信息与传输状态使用同一份读数。Apipost 集合 1.4.0 包含视频遥测、会议快照、观看与停止观看示例。订阅自己的流会返回 HTTP 403 和 `forbidden`。[公网 Apipost 集合](https://47.114.83.151/zwt-meeting/apipost.json)
